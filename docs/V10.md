# V10 Controlled Autonomy

Two items only. Box only, pi 1.4.0, real model. Test dir `/tmp/pimu-v10`.
Screenshots: `/workspace/pimu-shots/v10-*` (not in the repo).

## P0: per-bot safety mode

- Bot setting `mode`: `trusted` (default, native pi, unchanged) or `guarded`.
  Toggle in 编辑 Bot → 安全模式. Neither is an OS sandbox: L2 is app-level gating of
  pi tool calls; pi still runs with the local user's permissions.
- Guarded main session runs at `PIMU_LEVEL=0` with `PIMU_MODE=guarded`, so
  `pimu_task` is still registered and explicitly allowed. Every other call goes
  through the L2 rules: read-only tools and the read-only bash allowlist pass;
  writes outside cwd, non-allowlisted bash and MCP tools without `readOnlyHint`
  (e.g. `browser_navigate`) ask; dangerous commands ask too (the user is present),
  instead of the hard block used in jobs. Block reasons are tagged `[pimu guarded]`.
- Approvals for the main session use scope goal 0 / job 0. The server accepts them
  only when the bot is guarded (403 otherwise). Same hash, single use, TTLs as V9.
- They appear in the inbox and inline above the composer (批准一次 / 拒绝). The gate
  polls every 2s; on approve the blocked call runs once, on deny it is refused.
- Mode switch: an idle pi process is released at once, so the next message uses the
  new mode. A process that is replying keeps its old mode until it next starts.

## P1: approval counts from Pimu records

- Each job carries `approvals {approval_count, approved, denied, expired, pending}`
  counted from the inbox table (approved includes used). Shown on the job card.
- The result delivered to the main bot gets a factual line, e.g.
  `[Pimu] approvals: 3 requested, 2 approved, 1 denied`, marked as authoritative
  over the worker's own claim.

## Verified (real model, box)

1. Trusted bot: write outside cwd ran with no approval.
2. Guarded bot: the same write showed an inline card, approved in the UI, file written,
   approval `used`.
3. Guarded bot delegated a job via `pimu_task`; the job asked 3 times (2 approved,
   1 denied); the card showed 审批 3（批准 2，拒绝 1） and the main bot received and
   repeated `[Pimu] approvals: 3 requested, 2 approved, 1 denied`.
4. Switching an idle bot trusted → guarded took effect on the next message (denied →
   no file); switching back → no approval again.
5. `go test ./...`: 45 top-level tests, 0 failures.

## Not verified

- Switching mode while a reply is streaming (designed: next start).
- Guarded with Playwright MCP tools in the main chat, long waits, iPhone, Telegram.
